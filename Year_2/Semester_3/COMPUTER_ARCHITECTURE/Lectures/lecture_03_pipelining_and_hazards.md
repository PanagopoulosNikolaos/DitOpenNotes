# Διάλεξη 3: Διασωλήνωση (Pipelining) και Κίνδυνοι (Hazards)

## 1. Βασικές Αρχές Διασωλήνωσης
Η διασωλήνωση (pipelining) είναι μια τεχνική υλοποίησης κατά την οποία πολλαπλές εντολές επικαλύπτονται χρονικά κατά την εκτέλεσή τους.

### 1.1 Βασικά Στάδια Κλασικής Διασωλήνωσης 5 Σταδίων
1. **IF (Instruction Fetch):** Ανάκληση εντολής και ενημέρωση $PC$.
2. **ID (Instruction Decode):** Αποκωδικοποίηση εντολής και ανάγνωση καταχωρητών.
3. **EX (Execution):** Εκτέλεση αριθμητικών πράξεων ή υπολογισμός διευθύνσεων.
4. **MEM (Memory Access):** Πρόσβαση στη μνήμη δεδομένων.
5. **WB (Write Back):** Επανεγγραφή αποτελέσματος στο Register File.

### 1.2 Επιτάχυνση (Speedup)
Υπό ιδανικές συνθήκες, η επιτάχυνση που προσφέρει μια διασωλήνωση $k$ σταδίων είναι:
$$\text{Speedup} = \frac{\text{Χρόνος μη διασωληνωμένου}}{\text{Χρόνος διασωληνωμένου}} \approx k$$
Στην πράξη, η επιτάχυνση περιορίζεται από τις καθυστερήσεις των καταχωρητών διασωλήνωσης (pipeline registers) και τους κινδύνους (hazards).

## 2. Κατηγορίες Κινδύνων (Pipeline Hazards)

### 2.1 Δομικοί Κίνδυνοι (Structural Hazards)
Συμβαίνουν όταν δύο ή περισσότερες εντολές απαιτούν τον ίδιο πόρο υλικού στον ίδιο κύκλο ρολογιού.
- **Παράδειγμα:** Ταυτόχρονη πρόσβαση στη μνήμη για ανάκληση εντολής (IF) και ανάγνωση/εγγραφή δεδομένων (MEM) όταν υπάρχει ενιαία μνήμη Von Neumann.
- **Επίλυση:** Διαχωρισμός σε ξεχωριστή μνήμη εντολών και μνήμη δεδομένων (Harvard Architecture ή ξεχωριστές L1 I-Cache & D-Cache).

### 2.2 Κίνδυνοι Δεδομένων (Data Hazards)
Συμβαίνουν όταν μια εντολή εξαρτάται από το αποτέλεσμα προηγούμενης εντολής που δεν έχει ολοκληρώσει ακόμα τη φάση εγγραφής της (RAW - Read After Write).

```assembly
add $s0, $t0, $t1   # $s0 παράγεται στο στάδιο WB (κύκλος 5)
sub $t2, $s0, $t3   # $s0 διαβάζεται στο στάδιο ID (κύκλος 3) -> Σφάλμα δεδομένων!
```

#### Τεχνικές Επίλυσης:
1. **Προώθηση Δεδομένων (Data Forwarding / Bypassing):**
   - Τα δεδομένα περνούν απευθείας από την έξοδο του σταδίου EX/MEM ή MEM/WB στις εισόδους της ALU του σταδίου ID/EX χωρίς να αναμένεται η εγγραφή στο Register File.
2. **Καθυστέρηση Διασωλήνωσης (Pipeline Stall / Bubble):**
   - Στην περίπτωση Load-Use Data Hazard (`lw` ακολουθούμενη άμεσα από εντολή που χρησιμοποιεί το φορτωμένο δεδομένο), η προώθηση δεν επαρκεί και απαιτείται εισαγωγή 1 κύκλου καθυστέρησης (stall bubble).

### 2.3 Κίνδυνοι Ελέγχου (Control Hazards)
Προκύπτουν από εντολές διακλάδωσης (`beq`, `bne`, `j`), όπου η επόμενη εντολή προς εκτέλεση δεν είναι γνωστή μέχρι να υπολογιστεί η συνθήκη και η διεύθυνση στόχου.

#### Τεχνικές Αντιμετώπισης:
1. **Καθυστέρηση Διακλάδωσης (Branch Delay Slot):**
   - Η αρχιτεκτονική ορίζει ότι η εντολή ακριβώς μετά τη διακλάδωση εκτελείται πάντα.
2. **Στατική Πρόβλεψη Διακλάδωσης (Static Branch Prediction):**
   - Πρόβλεψη ότι η διακλάδωση δεν λαμβάνεται ποτέ (Predict Not Taken) ή πρόβλεψη βάσει φοράς (προς τα πίσω λαμβάνεται για βρόχους, προς τα εμπρός δεν λαμβάνεται).
3. **Δυναμική Πρόβλεψη Διακλάδωσης (Dynamic Branch Prediction):**
   - Χρήση Branch History Table (BHT), 2-bit Saturating Counters και Branch Target Buffer (BTB).
