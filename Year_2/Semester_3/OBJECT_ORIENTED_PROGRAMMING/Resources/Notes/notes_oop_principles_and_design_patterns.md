# Σημειώσεις: Αρχές Σχεδίασης OOP, SOLID και Σχεδιαστικά Πρότυπα

## 1. Οι Αρχές Σχεδίασης SOLID
Οι αρχές SOLID αποτελούν το θεμέλιο της καθαρής αντικειμενοστραφούς σχεδίασης λογισμικού:

1. **S - Single Responsibility Principle (SRP):** Μία κλάση πρέπει να έχει έναν και μοναδικό λόγο αλλαγής (μονή ευθύνη).
2. **O - Open/Closed Principle (OCP):** Οι οντότητες λογισμικού πρέπει να είναι ανοιχτές προς επέκταση (extension), αλλά κλειστές προς τροποποίηση (modification).
3. **L - Liskov Substitution Principle (LSP):** Τα αντικείμενα μιας παραγόμενης κλάσης πρέπει να μπορούν να αντικαταστήσουν αντικείμενα της βασικής κλάσης χωρίς να αλλοιώνεται η ορθότητα του προγράμματος.
4. **I - Interface Segregation Principle (ISP):** Οι πελάτες δεν πρέπει να αναγκάζονται να εξαρτώνται από διεπαφές τις οποίες δεν χρησιμοποιούν (προτίμηση πολλών μικρών διεπαφών αντί μίας μεγάλης).
5. **D - Dependency Inversion Principle (DIP):** Οι κλάσεις υψηλού επιπέδου δεν πρέπει να εξαρτώνται από κλάσεις χαμηλού επιπέδου. Και οι δύο πρέπει να εξαρτώνται από αφαιρέσεις (interfaces).

## 2. Βασικά Σχεδιαστικά Πρότυπα (Design Patterns - GoF)

### 2.1 Singleton Pattern
Εξασφαλίζει ότι μια κλάση έχει μόνο ένα στιγμιότυπο (instance) και παρέχει καθολικό σημείο πρόσβασης σε αυτό.
- Στη σύγχρονη C++, η ασφαλέστερη υλοποίηση είναι το **Meyers' Singleton** με χρήση static τοπικής μεταβλητής.

### 2.2 Factory Method Pattern
Ορίζει μια διεπαφή για τη δημιουργία ενός αντικειμένου, αλλά επιτρέπει στις υποκλάσεις να αποφασίσουν ποια κλάση θα αρχικοποιηθεί.

### 2.3 Observer Pattern (Εκδότης - Συνδρομητής)
Ορίζει σχέση εξάρτησης ένα-προς-πολλά μεταξύ αντικειμένων, έτσι ώστε όταν ένα αντικείμενο αλλάζει κατάσταση, όλοι οι εξαρτώμενοι παρατηρητές (observers) να ειδοποιούνται αυτόματα.

### 2.4 Strategy Pattern
Ορίζει μια οικογένεια αλγορίθμων, ενθυλακώνει τον καθένα, και τους καθιστά εναλλάξιμους κατά τον χρόνο εκτέλεσης.
