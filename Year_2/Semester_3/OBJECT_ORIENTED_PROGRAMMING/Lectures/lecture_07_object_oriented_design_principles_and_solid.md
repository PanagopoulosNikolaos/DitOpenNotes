# Διάλεξη 07: Αρχές Αντικειμενοστραφούς Σχεδίασης και Αρχές SOLID

## 1. Θεμελιώδεις Αρχές Σχεδίασης Λογισμικού
- **Υψηλή Συνοχή (High Cohesion):** Κάθε ενότητα/κλάση πρέπει να εκτελεί ένα σύνολο στενά συνδεδεμένων και εστιασμένων λειτουργιών.
- **Χαμηλή Σύζευξη (Low Coupling):** Ελαχιστοποίηση των αμοιβαίων εξαρτήσεων μεταξύ διαφορετικών κλάσεων, επιτρέποντας ανεξάρτητη τροποποίηση και επανάχρηση.
- **Σύνθεση έναντι Κληρονομικότητας (Composition over Inheritance):** Προτίμηση στη σχέση "has-a" έναντι της "is-a" για μεγαλύτερη ευελιξία και αποφυγή άκαμπτων ιεραρχιών.

## 2. Οι Πέντε Αρχές SOLID

### 2.1 Single Responsibility Principle (SRP - Αρχή Μοναδικής Ευθύνης)
- *«Μια κλάση πρέπει να έχει έναν και μόνο ένα λόγο για να αλλάξει.»*
- Διαχωρισμός επιχειρησιακής λογικής (business logic), διαχείρισης δεδομένων (persistence) και παρουσίασης (UI).

### 2.2 Open/Closed Principle (OCP - Αρχή Ανοικτού/Κλειστού)
- *«Οι οντότητες λογισμικού πρέπει να είναι ανοικτές για επέκταση, αλλά κλειστές για τροποποίηση.»*
- Επίτευξη μέσω αφηρημένων κλάσεων και πολυμορφισμού: νέα λειτουργικότητα προστίθεται με νέες παράγωγες κλάσεις, χωρίς τροποποίηση του υπάρχοντος ελεγμένου κώδικα.

### 2.3 Liskov Substitution Principle (LSP - Αρχή Υποκατάστασης Liskov)
- *«Τα αντικείμενα μιας υποκλάσης πρέπει να μπορούν να αντικαταστήσουν τα αντικείμενα της υπερκλάσης χωρίς να αλλοιώνεται η ορθότητα του προγράμματος.»*
- Κλασική παραβίαση: Η κλάση `Square` που κληρονομεί από την `Rectangle`.

### 2.4 Interface Segregation Principle (ISP - Αρχή Διαχωρισμού Διεπαφών)
- *«Οι πελάτες δεν πρέπει να εξαναγκάζονται να εξαρτώνται από διεπαφές που δεν χρησιμοποιούν.»*
- Προτίμηση σε πολλές μικρές, στοχευμένες διεπαφές έναντι μίας μονολιθικής («παχιάς») διεπαφής (Fat Interface).

### 2.5 Dependency Inversion Principle (DIP - Αρχή Αντιστροφής Εξαρτήσεων)
- *«Τα υψηλού επιπέδου αρθρώματα δεν πρέπει να εξαρτώνται από χαμηλού επιπέδου αρθρώματα. Και τα δύο πρέπει να εξαρτώνται από αφαιρέσεις (abstractions).»*
- Υλοποίηση μέσω τεχνικών όπως **Έγχυση Εξαρτήσεων (Dependency Injection)**.
