## Deduplication Decision Tree

Before writing any exercise from a time-variant file, apply the following decision tree to determine whether to include it:

```
Is the exercise's core mathematical structure (distribution type, formula used,
solution method) identical to one already included from the standard file?
│
├── YES → Are the numerical values just a domain re-skin (e.g., "height in cm"
│         replaced by "latency in ms") with no change to solution approach?
│         │
│         ├── YES → DROP the time-variant exercise. Do not include it.
│         │
│         └── NO  → Does the time domain introduce a qualitatively different
│                   gotcha, edge case, or real-world consideration?
│                   │
│                   ├── YES → INCLUDE as a variant exercise with a note:
│                   │         > **Time-Domain Note:** [state the unique aspect]
│                   │
│                   └── NO  → DROP the time-variant exercise.
│
└── NO  → INCLUDE the exercise unconditionally.
```

> [!IMPORTANT]
> Every unique formula, definition, callout block, theorem, and R code snippet must be
> retained regardless of the exercise deduplication decision above. Deduplication applies
> ONLY to worked exercises with identical solution structure.

## Operational Execution Strategy (Leveraging 1M Context & High Thinking)

### Pre-Phase Thinking Protocol

Before writing a single line of any consolidated phase file, activate extended internal reasoning to perform the following analysis:

1. **Section Inventory:** Load all source files for the phase simultaneously. List every unique `##` and `###` heading across both standard and time-variant files.
2. **Formula Audit:** Catalogue all distinct formulas. Flag any notation inconsistencies across files (e.g., $\bar{x}$ vs $\mu$, $s^2$ vs $\sigma^2$ for sample vs population).
3. **Exercise Inventory:** Number every worked exercise found across both files. Apply the Deduplication Decision Tree to each time-variant exercise. Produce an inclusion/exclusion list before writing.
4. **Gotcha Extraction:** List every `> [!NOTE]`, `> [!WARNING]`, callout, or "Common Mistake" block from time-variant files that is not present in the standard file.
5. **R Code Audit:** List every unique ` ```r ` block from both files; flag any duplicates.

Only after completing the above reasoning should the agent begin writing the output file.

phase_files = sorted(glob.glob('Resources/Phases/*.md'))

## Document Structure Template

Every phase file written to `Resources/Phases/` must follow this exact structure:

```markdown
# Phase N: [Phase Name]

## Table of Contents
- [Section N.1: Topic Title](#section-n1-topic-title)
- [Section N.2: Topic Title](#section-n2-topic-title)
- ...
- [Phase N Summary](#phase-n-summary)

---

## Section N.1: [Topic Title]

### Core Theory & Definitions
[Merged conceptual explanations from both source files. Use the standard file as
the primary structural template. Integrate unique definitions from time files.]

### Mathematical Formulas & Derivations
[All unique formulas using standard LaTeX: inline $formula$, block $$formula$$.]
[Ensure unified notation: $f_i$, $h_i$, $F_i$, $H_i$, $E[X]$, $\text{Var}(X)$.]
[Flag any notation conflicts encountered and resolve them explicitly.]

> **Practical / Time-Domain Note:**
> [Extract unique gotchas and real-world considerations from time-variant files.
> Only include if genuinely distinct from the standard file's content.]

### Worked Exercises

#### Exercise 1: [Descriptive Title]
**Problem:** [Full problem statement]

**Solution:**
[Step-by-step solution]

#### Exercise 2: [Descriptive Title]
...

[Minimum 10 exercises per section. Exercises are numbered continuously from 1 to N
within the section. Time-domain variants that pass the Deduplication Decision Tree
are included with a Time-Domain Note blockquote below the solution.]

### R Implementation
```r
# Descriptive comment explaining what this block demonstrates
# ...R code...
```

---

## Phase N Summary
[Concise 5-8 sentence summary covering: core concepts, key formulas, critical
distinctions (population vs sample, discrete vs continuous, etc.), and the most
common exam-relevant gotchas from the time-domain variants.]
```

### Formatting Rules (Mandatory)

| Rule | Specification |
|---|---|
| Emojis | Strictly prohibited. Zero tolerance. |
| Inline math | `$...$` only. No `\(...\)` or bare text formulas. |
| Block math | `$$...$$` only. No `\[...\]`. |
| H1 headings | One per file: `# Phase N: [Name]` |
| H2 headings | Major sections: `## Section N.X:` and `## Phase N Summary` |
| H3 headings | Subsections: `### Core Theory`, `### Worked Exercises`, `### R Implementation` |
| H4 headings | Individual exercises: `#### Exercise N: [Title]` |
| Tables | Pipe-delimited with header separator row. Align columns where practical. |
| Code blocks | Language-tagged: ` ```r `, ` ```bash `, ` ```python ` |
| Callouts | Use `> **Label:** text` for Practical/Time-Domain Notes |
