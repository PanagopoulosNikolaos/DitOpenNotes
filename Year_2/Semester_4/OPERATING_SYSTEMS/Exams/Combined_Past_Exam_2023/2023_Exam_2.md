# Εξέταση Λειτουργικών Συστημάτων - Απρίλιος 2023

## ΘΕΜΑ 1 (3 μονάδες)

(α) Ποιο είναι το βασικό μειονέκτημα της χρήσης ενεργού αναμονής (busy-waiting) στην επίλυση του προβλήματος αμοιβαίου αποκλεισμού.

---

**Λύση:**

Το βασικό μειονέκτημα της ενεργού αναμονής (busy-waiting) είναι η σπατάλη κύκλων της Κεντρικής Μονάδας Επεξεργασίας (CPU). Η διεργασία που επιχειρεί να εισέλθει στον κρίσιμο τομέα εκτελεί επαναληπτικά έναν βρόχο ελέγχου της τιμής του κλειδώματος (spin loop), χωρίς να παραδίδει τον επεξεργαστή στο Λειτουργικό Σύστημα (ΛΣ). Αυτό έχει ως αποτέλεσμα:

- Χαμηλή χρησιμοποίηση (utilization) της CPU.
- Σπατάλη ενέργειας.
- Μείωση της συνολικής απόδοσης του συστήματος, ιδιαίτερα όταν ο κρίσιμος τομέας διαρκεί αρκετό χρόνο ή όταν υπάρχουν πολλές διεργασίες σε αναμονή.

Σε αντίθεση με τις σηματοφόρους ή τα mutex με sleep, η busy-waiting δεν επιτρέπει στον scheduler να εκτελέσει άλλη έτοιμη διεργασία.

(β) Εξηγήστε τι θα συμβεί σε ένα πρόγραμμα που χρησιμοποιεί τη σηματοφόρο SEM2 με τρέχουσα τιμή 0 αν καλέσει την μέθοδο wait (SEM2).

---

**Λύση:**

Όταν η τρέχουσα τιμή της σηματοφόρου SEM2 είναι 0 και η διεργασία καλέσει `wait(SEM2)`:

1. Η τιμή της σηματοφόρου μειώνεται κατά 1 (γίνεται -1).
2. Η διεργασία μεταβαίνει στην κατάσταση **αναμονής** (blocked / waiting state).
3. Η διεργασία παραμένει σε αυτή την κατάσταση μέχρι κάποια άλλη διεργασία να καλέσει `signal(SEM2)`.
4. Όταν γίνει το signal, η τιμή αυξάνεται σε 0 και η διεργασία ξυπνάει (μεταβαίνει σε ready queue) και συνεχίζει την εκτέλεσή της μετά την κλήση wait.

Αν η υλοποίηση χρησιμοποιεί "waiting queue", η διεργασία εισάγεται σε ουρά αναμονής της σηματοφόρου.

(γ) Γιατί ένα πολυπρογραμματιστικό (multiprogramming) σύστημα κάνει καλύτερη χρησιμοποίηση (Utilization) της Κεντρικής Μονάδας Επεξεργασίας (CPU);

---

**Λύση:**

Σε ένα πολυπρογραμματιστικό σύστημα, η καλύτερη χρησιμοποίηση της CPU οφείλεται στον **χρονοπρογραμματισμό** (scheduling). Όταν μια διεργασία εκτελεί I/O ή αναμένει κάποιο γεγονός (π.χ. σήμα, mutex), μεταβαίνει σε κατάσταση blocked. Το ΛΣ μπορεί αμέσως να επιλέξει και να εκτελέσει μια άλλη διεργασία που βρίσκεται στην ουρά "έτοιμες" (ready queue). 

Έτσι:
- Ο χρόνος που η CPU θα ήταν αδρανής (idle) σε μονοπρογραμματιστικό σύστημα, χρησιμοποιείται παραγωγικά.
- Αυξάνεται το CPU utilization (ποσοστό χρόνου που η CPU εκτελεί χρήσιμη εργασία).
- Μειώνεται ο μέσος χρόνος αναμονής των διεργασιών.

(δ) Ποια κλήση συστήματος μπορούμε να χρησιμοποιήσουμε σε ένα σύστημα Unix/Linux για να δημιουργήσουμε μια διεργασία και τι επιστρέφει σαν τιμή.

---

**Λύση:**

Η κλήση συστήματος είναι η `fork()`.

Τιμές επιστροφής:
- **0**: Επιστρέφεται στη **θυγατρική διεργασία** (child process).
- **Θετικός ακέραιος (PID της θυγατρικής)**: Επιστρέφεται στη **γονική διεργασία** (parent process).
- **-1**: Σε περίπτωση σφάλματος (π.χ. υπέρβαση του ορίου διεργασιών του χρήστη ή του συστήματος, ή έλλειψη πόρων).

Μετά το fork, και οι δύο διεργασίες συνεχίζουν την εκτέλεση από το σημείο αμέσως μετά την κλήση, αλλά με διαφορετικό PID και ξεχωριστό address space (με copy-on-write σε σύγχρονα συστήματα).

## ΘΕΜΑ 2 (3 μονάδες)

Σε ένα σύστημα, έχουμε διαθέσιμα δύο (2) στιγμιότυπα από τον πόρο Α και ένα (1) στιγμιότυπο από τον πόρο Β. Στη διεργασία P1 έχει εκχωρηθεί ένας πόρος Β και η P1 έχει κάνει αίτηση για έναν πόρο Α. Στη διεργασία P2 έχει εκχωρηθεί ένας πόρο Α και η P2 έχει κάνει αίτηση για έναν πόρο Β.

(α) Δημιουργήστε ένα γράφημα εκχώρησης πόρων αυτής της περίπτωσης

---

**Λύση:**

**Γράφημα εκχώρησης πόρων (Resource Allocation Graph):**

```
          +---------+          +---------+
          |   A     |          |   B     |
          | [•][•]  |          |  [•]    |
          +---------+          +---------+
             |   ^                ^   |
             |   |                |   |
    allocated|   |request         |   |request
    to P2    |   |P1              |   |P2
             v   |                |   v
          +---------+          +---------+
          |  P2     |          |  P1     |
          +---------+          +---------+
```

**Επεξήγηση βελών:**
- A (ένα στιγμιότυπο) → P2 : Ο πόρος Α έχει εκχωρηθεί στη P2.
- P1 → A : Η P1 έχει κάνει αίτηση για πόρο Α (request edge).
- B → P1 : Ο πόρος Β έχει εκχωρηθεί στη P1.
- P2 → B : Η P2 έχει κάνει αίτηση για πόρο Β (request edge).

Υπάρχει **κύκλος**: P1 → A → P2 → B → P1.

(β) Εξηγήστε αν στην περίπτωσή μας υπάρχει ή δεν υπάρχει αδιέξοδο.

---

**Λύση:**

**Δεν υπάρχει αδιέξοδο (deadlock) σε αυτή την κατάσταση.**

Αν και υπάρχει κύκλος στο γράφημα εκχώρησης πόρων, επειδή ο πόρος Α διαθέτει **πολλαπλά στιγμιότυπα** (2 συνολικά), και μόνο 1 έχει εκχωρηθεί (στη P2), υπάρχει **1 ελεύθερο στιγμιότυπο** του Α.

Το ΛΣ μπορεί να ικανοποιήσει αμέσως την αίτηση της P1 για Α (αφού available[A] = 1 ≥ 1). 

Μετά την εκχώρηση:
- Η P1 κατέχει πλέον Α και Β.
- Η P1 μπορεί να ολοκληρώσει τον κρίσιμο τομέα της, να απελευθερώσει και τους δύο πόρους.
- Στη συνέχεια η P2 μπορεί να λάβει τον Β και να ολοκληρώσει.

Επειδή η αίτηση της P1 μπορεί να ικανοποιηθεί με τους υπάρχοντες διαθέσιμους πόρους, η κατάσταση είναι **ασφαλής** και δεν έχει δημιουργηθεί αδιέξοδο. (Σημείωση: για πόρους με πολλαπλά στιγμιότυπα, η ύπαρξη κύκλου δεν συνεπάγεται απαραίτητα deadlock· απαιτείται αλγόριθμος μείωσης του γράφου.)

## ΘΕΜΑ 3 (2 μονάδες)

Σε ένα υπολογιστικό σύστημα έχουμε διαθέσιμες τρεις κατηγορίες πόρων (R1, R2 και R3) και κάποια χρονική στιγμή τρέχουν τέσσερις διεργασίες (P1, P2 και P3). Οι μέγιστες απαιτήσεις σε πόρους για κάθε διεργασία και ο συνολικός αριθμός πόρων κάθε κατηγορίας εμφανίζονται στις περιοχές Max και Total στο ακόλουθο διάγραμμα. Αν αναθέσουμε στις διεργασίες τις ποσότητες πόρων που εμφανίζονται στο τμήμα Allocated, εξηγήστε αν η κατάσταση αυτή θεωρείται ασφαλής ως προς την δημιουργία αδιεξόδου. (Βοήθημα: Μπορείτε να χρησιμοποιήσετε τις θέσεις Available και Needed για να υπολογίσετε τους διαθέσιμους πόρους και τις τρέχουσες ανάγκες των διεργασιών).


| | Max R1 | Max R2 | Max R3 | Allocated R1 | Allocated R2 | Allocated R3 | Needed R1 | Needed R2 | Needed R3 | Total R1 | Total R2 | Total R3 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| P1 | 3 | 1 | 1 | 2 | 0 | 1 | | | | 6 | 2 | 4 |
| P2 | 3 | 2 | 1 | 2 | 1 | 1 | | | | Available R1 | Available R2 | Available R3 |
| P3 | 2 | 2 | 3 | 2 | 1 | 2 | | | | | | |


---

**Λύση:**

**Υπολογισμός Needed (Max - Allocated) για κάθε διεργασία:**

- **P1**: Needed = (3-2, 1-0, 1-1) = **(1, 1, 0)**
- **P2**: Needed = (3-2, 2-1, 1-1) = **(1, 1, 0)**
- **P3**: Needed = (2-2, 2-1, 3-2) = **(0, 1, 1)**

**Υπολογισμός Available (Total - Sum Allocated):**

Sum Allocated:
- R1: 2 + 2 + 2 = **6**
- R2: 0 + 1 + 1 = **2**
- R3: 1 + 1 + 2 = **4**

Available = Total - Sum Allocated = (6-6, 2-2, 4-4) = **(0, 0, 0)**

**Έλεγχος ασφαλούς κατάστασης (Banker's Algorithm - Safety Check):**

Αναζητούμε διεργασία της οποίας το Needed ≤ Available:

- P1: (1,1,0) ≰ (0,0,0)
- P2: (1,1,0) ≰ (0,0,0)
- P3: (0,1,1) ≰ (0,0,0)   (1 > 0 για R2 και R3)

**Καμία διεργασία δεν μπορεί να ολοκληρωθεί** με τους τρέχοντες διαθέσιμους πόρους. Δεν υπάρχει ασφαλής ακολουθία (safe sequence). 

**Συμπέρασμα:** Η κατάσταση είναι **μη ασφαλής** (unsafe state). Υπάρχει κίνδυνος δημιουργίας αδιεξόδου (deadlock), καθώς καμία διεργασία δεν μπορεί να προχωρήσει στην ολοκλήρωσή της και να απελευθερώσει πόρους για τις υπόλοιπες.

**Λύση:**

**Σωστή απάντηση: δ) Η διεργασία P3**

**Ανάλυση:**

Υπάρχει **κύκλος** μεταξύ P1 και P2:
- R1 → P1 (P1 κατέχει R1)
- P2 → R1 (P2 αιτείται R1)
- P1 → R2 (P1 αιτείται R2)
- R2 → P2 (P2 κατέχει R2)

Αυτός ο κύκλος δημιουργεί αδιέξοδο μεταξύ **P1 και P2** (δεν μπορούν να προχωρήσουν).

Ωστόσο, η **P3** δεν συμμετέχει στον κύκλο:
- R3 → P3 (P3 κατέχει R3)
- P3 → R4 (P3 αιτείται R4)

Το R4 εμφανίζεται με **3 στιγμιότυπα** και **κανένα δεν έχει εκχωρηθεί** (δεν υπάρχει βέλος από R4 προς κάποια διεργασία). Άρα available instances του R4 ≥ 1. Η P3 μπορεί να λάβει τον πόρο R4, να ολοκληρώσει την εκτέλεσή της και να τερματίσει.

Επομένως, η P3 **θα εκτελεστεί και θα ολοκληρωθεί**, ενώ P1 και P2 παραμένουν σε αδιέξοδο. Η P3 είναι η διεργασία που εκτελείται τελευταία (η μόνη που ολοκληρώνεται).

**Λύση:**

**Σωστή απάντηση: γ) P2.1, P2.2, P2.3, P2.4, P2.5, P1.1**

γ) αποθηκεύονται οι μεταβλητές και η δυναμικά παραχωρούμενη μνήμη

**Λύση:**

**Σωστή απάντηση: β) αποθηκεύονται οι τοπικές μεταβλητές των συναρτήσεων**

**Επεξήγηση:**

- **Stack (στοίβα)**: Αποθηκεύει το **activation record** κάθε κλήσης συνάρτησης (locals, παραμέτρους, return address, frame pointer). Αναπτύσσεται και συρρικνώνεται δυναμικά με τις κλήσεις/επιστροφές συναρτήσεων.

4. Κατά την μετάβαση της κατάστασης εκτέλεσης από «εκτελούμενη» σε «έτοιμη»

α) μια επιπρόσθετη διεργασία εισάγεται στο σύστημα  
β) η διεργασία έχει φθάσει στο μέγιστο επιτρεπτό όριο εκτέλεσής της  
γ) η διεργασία απαιτεί μια υπηρεσία από το ΛΣ που δεν θα εκτελεστεί άμεσα  
δ) η διεργασία αναμένει την απελευθέρωση μνήμης  

Απάντηση : ____

---

**Λύση:**

**Σωστή απάντηση: β) η διεργασία έχει φθάσει στο μέγιστο επιτρεπτό όριο εκτέλεσής της**

**Επεξήγηση:**

Η μετάβαση **running → ready** συμβαίνει κυρίως λόγω **προεκχώρησης** (preemption):

- Όταν η διεργασία έχει εξαντλήσει το **time quantum** (το μέγιστο επιτρεπτό συνεχές διάστημα εκτέλεσης που της έχει δοθεί από τον scheduler).
- Ο scheduler μετακινεί τη διεργασία πίσω στην ready queue για να δώσει ευκαιρία σε άλλες έτοιμες διεργασίες.

Οι άλλες επιλογές:
- **α)** Αναφέρεται σε δημιουργία νέας διεργασίας (fork), όχι σε αλλαγή κατάστασης.
- **γ)** Αν η υπηρεσία μπλοκάρει (π.χ. I/O), η μετάβαση είναι **running → blocked/waiting**, όχι σε ready.
- **δ)** Αναμονή για μνήμη συνήθως οδηγεί σε blocked state.
