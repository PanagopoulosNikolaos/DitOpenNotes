## QUESTION 1 (3 units)

(a) What is the main disadvantage of using busy-waiting in solving the mutual exclusion problem?

---

**Solution:**

The main disadvantage of busy-waiting is the waste of Central Processing Unit (CPU) cycles. The process attempting to enter the critical section repeatedly executes a lock value check loop (spin loop), without yielding the processor to the Operating System (OS). This results in:

- Low CPU utilization.
- Energy waste.
- Reduced overall system performance, especially when the critical section is long-running or when there are many processes waiting.

Unlike semaphores or mutex with sleep, busy-waiting does not allow the scheduler to execute another ready process.

(b) Explain what will happen to a program that uses semaphore SEM2 with current value 0 if it calls the wait (SEM2) method.

---

**Solution:**

When the current value of semaphore SEM2 is 0 and the process calls `wait(SEM2)`:

1. The semaphore value decreases by 1 (becomes -1).
2. The process transitions to the **waiting** (blocked / waiting state).
3. The process remains in this state until another process calls `signal(SEM2)`.
4. When the signal occurs, the value increases to 0 and the process wakes up (transitions to ready queue) and continues execution after the wait call.

If the implementation uses a "waiting queue", the process is inserted into the semaphore's waiting queue.

(c) Why does a multiprogramming system achieve better CPU Utilization?

---

**Solution:**

In a multiprogramming system, better CPU utilization is due to **scheduling**. When a process performs I/O or waits for an event (e.g., signal, mutex), it transitions to a blocked state. The OS can immediately select and execute another process from the "ready" queue.

Thus:
- Time that would be idle in a single-program system is used productively.
- CPU utilization increases (percentage of time CPU performs useful work).
- Average waiting time for processes decreases.

(d) What system call can we use in a Unix/Linux system to create a process, and what does it return as a value?

---

**Solution:**

The system call is `fork()`.

Return values:
- **0**: Returned to the **child process**.
- **Positive integer (Child's PID)**: Returned to the **parent process**.
- **-1**: In case of error (e.g., exceeding the user or system process limit, or resource shortage).

After the fork, both processes continue execution from the point immediately after the call, but with different PID and separate address space (with copy-on-write in modern systems).

## QUESTION 2 (3 units)

In a system, we have two (2) instances of resource A and one (1) instance of resource B available. Process P1 has been allocated one resource B and has requested one resource A. Process P2 has been allocated one resource A and has requested one resource B.

(a) Create a resource allocation graph for this case

---

**Solution:**

**Resource Allocation Graph:**

```
          +---------+          +---------+
          |   A     |          |   B     |
          | [•][•]  |          |  [•]    |
          +---------+          +---------+
             |   ^                ^   |
             |   |                |   |
    allocated|   |request         |   |request
    to P2    |   |P1              |   |P2
             v   |                |   v
          +---------+          +---------+
          |  P2     |          |  P1     |
          +---------+          +---------+
```

**Edge explanation:**
- A (one instance) → P2 : Resource A has been allocated to P2.
- P1 → A : P1 has requested resource A (request edge).
- B → P1 : Resource B has been allocated to P1.
- P2 → B : P2 has requested resource B (request edge).

There is a **cycle**: P1 → A → P2 → B → P1.

(b) Explain whether a deadlock exists or not in our case.

---

**Solution:**

**No deadlock exists in this state.**

Although there is a cycle in the resource allocation graph, because resource A has **multiple instances** (2 total), and only 1 has been allocated (to P2), there is **1 free instance** of A.

The OS can immediately satisfy P1's request for A (since available[A] = 1 ≥ 1).

After allocation:
- P1 now holds both A and B.
- P1 can complete its critical section and release both resources.
- Subsequently P2 can receive B and complete.

Because P1's request can be satisfied with the currently available resources, the state is **safe** and no deadlock has been created. (Note: for resources with multiple instances, the presence of a cycle does not necessarily imply deadlock; a graph reduction algorithm is required.)

## QUESTION 3 (2 units)

In a computing system we have three categories of resources (R1, R2 and R3) and at some point in time four processes are running (P1, P2 and P3). The maximum resource requirements for each process and the total number of resources in each category are shown in the Max and Total sections of the following diagram. If we assign to the processes the resource quantities shown in the Allocated section, explain whether this state is considered safe with respect to deadlock creation. (Hint: You can use the Available and Needed fields to calculate the available resources and the current needs of the processes).


| | Max R1 | Max R2 | Max R3 | Allocated R1 | Allocated R2 | Allocated R3 | Needed R1 | Needed R2 | Needed R3 | Total R1 | Total R2 | Total R3 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| P1 | 3 | 1 | 1 | 2 | 0 | 1 | | | | 6 | 2 | 4 |
| P2 | 3 | 2 | 1 | 2 | 1 | 1 | | | | Available R1 | Available R2 | Available R3 |
| P3 | 2 | 2 | 3 | 2 | 1 | 2 | | | | | | |


---

**Solution:**

**Calculation of Needed (Max - Allocated) for each process:**

- **P1**: Needed = (3-2, 1-0, 1-1) = **(1, 1, 0)**
- **P2**: Needed = (3-2, 2-1, 1-1) = **(1, 1, 0)**
- **P3**: Needed = (2-2, 2-1, 3-2) = **(0, 1, 1)**

**Calculation of Available (Total - Sum Allocated):**

Sum Allocated:
- R1: 2 + 2 + 2 = **6**
- R2: 0 + 1 + 1 = **2**
- R3: 1 + 1 + 2 = **4**

Available = Total - Sum Allocated = (6-6, 2-2, 4-4) = **(0, 0, 0)**

**Safe state check (Banker's Algorithm - Safety Check):**

We look for a process whose Needed ≤ Available:

- P1: (1,1,0) ≰ (0,0,0)
- P2: (1,1,0) ≰ (0,0,0)
- P3: (0,1,1) ≰ (0,0,0)   (1 > 0 for R2 and R3)

**No process can complete** with the current available resources. There is no safe sequence.

**Conclusion:** The state is **unsafe**. There is a risk of deadlock creation, as no process can proceed to completion and release resources for the remaining processes.

## QUESTION 4 (2 units)

1. According to the diagram in the figure, which process will be executed last?

```
    +---------+ +---------+
    | R1 | | R3 |
    | [•] | | [•] |
    +---------+ +---------+
      | ^ ^ |
      | | | |
      v | | v
   ( P1 ) | ( P2 ) ( P3 )
      | | ^ |
      | | | |
      v | | v
    +---------+ +---------+
    | [•] [•] | | [•] |
    | R2 | | [•] |
    +---------+ | [•] |
                                        | R4 |
                                        +---------+
* Arrow Direction Legend:
  R1 -> P1
  P2 -> R1
  P1 -> R2
  R2 -> P2
  P2 -> R3
  R3 -> P3
  P3 -> R4
```

a) None, because a deadlock will occur
b) Process P1
c) Process P2
d) Process P3

Answer: ____

---

**Solution:**

**Correct answer: d) Process P3**

**Analysis:**

There is a **cycle** between P1 and P2:
- R1 → P1 (P1 holds R1)
- P2 → R1 (P2 requests R1)
- P1 → R2 (P1 requests R2)
- R2 → P2 (P2 holds R2)

This cycle creates a deadlock between **P1 and P2** (they cannot proceed).

However, **P3** is not part of the cycle:
- R3 → P3 (P3 holds R3)
- P3 → R4 (P3 requests R4)

R4 appears to have **3 instances** and **none has been allocated** (there is no edge from R4 to any process). Thus available instances of R4 ≥ 1. P3 can receive resource R4, complete its execution, and terminate.

Therefore, P3 **will be executed and completed**, while P1 and P2 remain in deadlock. P3 is the process that executes last (the only one that completes).

2. Consider the following semaphore usage scenario by two processes, with A, B, C, D being independent code sections.

```
| Process P1 | Process P2 |
| --- | --- |
| P1.1 wait(S) | P2.1 wait(Q) |
| P1.2 wait(Q) | P2.2 wait(S) |
| P1.3 A | P2.3 C |
| P1.4 B | P2.4 D |
| P1.5 signal(Q) | P2.5 signal(S) |
| P1.6 signal(S) | P2.6 signal(Q) |
```

Which of the following step combinations can be completed?

a) P1.1, P2.1, P2.2, P2.3, P1.2, P1.3
b) P1.1, P1.2, P1.3, P2.1, P1.4, P2.2
c) P2.1, P2.2, P2.3, P2.4, P2.5, P1.1
d) P2.1, P1.1, P1.2, P1.3, P2.2, P2.3

Answer : ____

---

**Solution:**

**Correct answer: c) P2.1, P2.2, P2.3, P2.4, P2.5, P1.1**

**Analysis (with initial values S = 1, Q = 1):**

- **a)**: P1.1 (wait(S) → S=0), P2.1 (wait(Q) → Q=0), P2.2 (wait(S) → S=-1, **blocks**). P2.3 cannot execute because P2 has blocked at P2.2. **Impossible**.
- **b)**: P1.1 (S=0), P1.2 (wait(Q) → Q=0), P1.3 (A). Then P2.1 (wait(Q) → Q=-1, **blocks**). P2 cannot proceed. **Impossible**.
- **c)**: P2 executes **all** its steps first: wait(Q), wait(S), C, D, signal(S), signal(Q). All waits succeed (initial values 1). After the signals, P1.1 (wait(S)) executes normally. **Possible** (P2 completes fully before P1 starts).
- **d)**: P2.1 (Q=0), P1.1 (S=0), P1.2 (wait(Q) → Q=-1, **blocks**). P1.3 cannot execute. **Impossible**.

Only combination **c)** can be completed without premature blocking.

3. In the stack area of a process:

a) the code and variables are stored
b) local variables of functions are stored
c) variables and dynamically allocated memory are stored
d) the code executed by the processor is stored

Answer: ____

---

**Solution:**

**Correct answer: b) local variables of functions are stored**

**Explanation:**

- **Stack**: Stores the **activation record** of each function call (locals, parameters, return address, frame pointer). It grows and shrinks dynamically with function calls/returns.
- **Code segment**: Contains executable code (does not change during execution).
- **Data segment / Heap**: Stores global/static variables and **dynamically allocated memory** (malloc/new).
- The stack does **not** contain code or heap memory.

4. During the transition from the "running" state to the "ready" state

a) an additional process is inserted into the system
b) the process has reached its maximum allowable execution limit
c) the process requires a service from the OS that will not be executed immediately
d) the process is waiting for memory release

Answer : ____

---

**Solution:**

**Correct answer: b) the process has reached its maximum allowable execution limit**

**Explanation:**

The **running → ready** transition occurs primarily due to **preemption**:

- When the process has exhausted its **time quantum** (the maximum allowable continuous execution period given to it by the scheduler).
- The scheduler moves the process back to the ready queue to give opportunity to other ready processes.

Other options:
- **a)** Refers to process creation (fork), not state change.
- **c)** If the service blocks (e.g., I/O), the transition is **running → blocked/waiting**, not to ready.
- **d)** Waiting for memory typically leads to blocked state.
