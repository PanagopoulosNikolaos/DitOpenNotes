# Διάλεξη 8: Προστασία, Ασφάλεια και Εικονικοποίηση (Protection, Security & Virtualization)

## 1. Αρχές Προστασίας σε Λειτουργικά Συστήματα
Η **προστασία (protection)** αναφέρεται στους εσωτερικούς μηχανισμούς ελέγχου της πρόσβασης που έχουν τα προγράμματα ή οι χρήστες στους πόρους του υπολογιστικού συστήματος (CPU, μνήμη, αρχεία, συσκευές).
Η **ασφάλεια (security)** είναι το ευρύτερο μέτρο προστασίας της ακεραιότητας, εμπιστευτικότητας και διαθεσιμότητας του συστήματος από κακόβουλες εξωτερικές απειλές.

### Η Αρχή των Ελάχιστων Προνομίων (Principle of Least Privilege)
Κάθε διεργασία, χρήστης ή στοιχείο συστήματος πρέπει να λειτουργεί χρησιμοποιώντας αποκλειστικά το ελάχιστο σύνολο δικαιωμάτων που απαιτείται για την εκτέλεση της συγκεκριμένης αποστολής του, και μόνο για τη χρονική διάρκεια που απαιτείται.
- Περιορίζει τη ζημιά σε περίπτωση σφάλματος ή παραβίασης ασφάλειας.

## 2. Μοντέλα Ελέγχου Πρόσβασης

### Ο Πίνακας Πρόσβασης (Access Matrix)
Ένα αφηρημένο μοντέλο όπου:
- **Γραμμές:** Περιοχές Προστασίας / Χρήστες / Διεργασίες (Domains).
- **Στήλες:** Αντικείμενα προς προστασία (Objects: αρχεία, συσκευές, μνήμη).
- **Κελί $A[D, O]$:** Το σύνολο των δικαιωμάτων πρόσβασης (read, write, execute) της περιοχής $D$ πάνω στο αντικείμενο $O$.

### Υλοποιήσεις του Πίνακα Πρόσβασης
Επειδή ο πίνακας πρόσβασης είναι εξαιρετικά αραιός (sparse), υλοποιείται στην πράξη με δύο τρόπους:
1. **Λίστες Ελέγχου Πρόσβασης (Access Control Lists - ACLs - κατά στήλη):**
   - Κάθε αντικείμενο διατηρεί μια λίστα με τις περιοχές/χρήστες και τα αντίστοιχα δικαιώματα.
   - Χρήση: Συστήματα αρχείων (UNIX file permissions: Owner/Group/Others, Windows NTFS ACLs).
2. **Λίστες Ικανοτήτων (Capability Lists / C-Lists - κατά γραμμή):**
   - Κάθε περιοχή/διεργασία διατηρεί έναν ασφαλή κατάλογο "εισιτηρίων" (capabilities) που της επιτρέπουν συγκεκριμένες πράξεις σε συγκεκριμένα αντικείμενα.
   - Χρήση: Μικροπυρήνες, σύγχρονες αρχιτεκτονικές ασφάλειας (Capsicum, seL4).

## 3. Απειλές και Ευπάθειες Λογισμικού Συστήματος

### Υπερχείλιση Ενδιάμεσης Μνήμης (Buffer Overflow)
- Συμβαίνει σε γλώσσες χωρίς αυτόματο έλεγχο ορίων πινάκων (όπως η C/C++), όταν εγγράφονται δεδομένα πέραν του δεσμευμένου μεγέθους buffer στη στοίβα (stack).
- **Επίθεση Stack Smashing:** Υπερκάλυψη της διεύθυνσης επιστροφής (return address) στο stack frame με τη διεύθυνση κακόβουλου κώδικα (shellcode).
- **Μηχανισμοί Προστασίας:**
  - *Stack Canaries:* Τυχαίες τιμές τοποθετημένες πριν τη διεύθυνση επιστροφής.
  - *Non-Executable Stack (NX bit / W^X):* Σελίδες μνήμης είναι είτε εγγράψιμες είτε εκτελέσιμες, ποτέ και τα δύο ταυτόχρονα.
  - *ASLR (Address Space Layout Randomization):* Τυχαιοποίηση των διευθύνσεων στοίβας, σωρού και βιβλιοθηκών κατά την εκκίνηση.

## 4. Εικονικοποίηση (Virtualization)
Η τεχνολογία που επιτρέπει την εκτέλεση πολλαπλών λειτουργικών συστημάτων (Guest OS) ταυτόχρονα πάνω από το ίδιο φυσικό υλικό (Host Hardware).

### Υπερεπόπτης (Hypervisor / Virtual Machine Monitor - VMM)
1. **Hypervisor Τύπου 1 (Bare-Metal):**
   - Εκτελείται απευθείας πάνω στο φυσικό υλικό χωρίς υποκείμενο λειτουργικό σύστημα (π.χ. VMware ESXi, KVM, Xen).
   - Μέγιστη απόδοση και απομόνωση.
2. **Hypervisor Τύπου 2 (Hosted):**
   - Εκτελείται ως εφαρμογή πάνω από ένα παραδοσιακό λειτουργικό σύστημα (π.χ. VirtualBox, VMware Workstation).
   - Μεγαλύτερο virtualization overhead.

### Τεχνικές Εικονικοποίησης CPU
- **Πλήρης Εικονικοποίηση (Full Virtualization):** Το Guest OS δεν γνωρίζει ότι εκτελείται σε εικονική μηχανή. Απαιτεί υποστήριξη από το υλικό (Hardware-Assisted Virtualization: Intel VT-x, AMD-V) για ασφαλή εκτέλεση ευαίσθητων προνομιούχων εντολών.
- **Παραεικονικοποίηση (Paravirtualization):** Το Guest OS τροποποιείται ώστε να γνωρίζει ότι είναι εικονικοποιημένο, καλώντας απευθείας τον hypervisor μέσω ειδικών κλήσεων (hypercalls).

## 5. Εικονικοποίηση σε Επίπεδο Λειτουργικού Συστήματος (Containers)
Τα Containers (Docker, Podman, LXC) μοιράζονται τον **ίδιο πυρήνα (Kernel)** του κεντρικού λειτουργικού συστήματος, παρέχοντας απομονωμένα περιβάλλοντα εκτέλεσης χρήστη:
- **Namespaces στο Linux:** Παρέχουν απομόνωση πόρων συστήματος:
  - `pid` (απομονωμένα δένδρα διεργασιών),
  - `net` (ανεξάρτητα δικτυακά interfaces και routing tables),
  - `mnt` (ξεχωριστά σημεία προσάρτησης συστημάτων αρχείων),
  - `ipc`, `user`, `uts`.
- **Control Groups (cgroups):** Επιβάλλουν αυστηρά όρια και μετρήσεις χρήσης φυσικών πόρων (ποσοστό CPU, όριο RAM, εύρος ζώνης δίσκου/δικτύου) ανά ομάδα διεργασιών.
- **Σύγκριση Containers vs Virtual Machines:**
  - Τα VMs προσφέρουν ισχυρότερη απομόνωση (ξεχωριστός πυρήνας) αλλά απαιτούν gigabytes μνήμης και λεπτά για εκκίνηση.
  - Τα Containers εκκινούν σε χιλιοστά του δευτερολέπτου, έχουν ελάχιστο footprint μνήμης και σχεδόν μηδενική υποβάθμιση απόδοσης.
