# Lecture 04: Memory Management and Virtual Memory

This lecture examines physical and virtual memory architectures: address binding, paging, the Translation Lookaside Buffer (TLB), page fault mechanisms, and page replacement algorithms (FIFO, Optimal, LRU).

---

## 1. Physical Memory Management and Address Binding

The Memory Management Unit (MMU) is hardware that translates logical (virtual) addresses generated by the CPU into physical addresses recognized by the memory controller:

```
[ CPU ] ---> Logical Address (p, d) ---> [ MMU / Page Table ] ---> Physical Address (f, d) ---> [ Physical RAM ]
```

### 1.1 Fragmentation
- **Internal Fragmentation:** Memory allocated to a process is larger than requested (e.g., allocating a full $4 \text{ KB}$ page when only $100 \text{ bytes}$ are used).
- **External Fragmentation:** Total free memory space is sufficient to satisfy a request, but storage is non-contiguous, preventing allocation (eliminated via Paging).

---

## 2. Paging Hardware and Address Translation

Paging partitions physical memory into fixed-size blocks called **frames**, and partitions logical memory into blocks of identical size called **pages** (typically $4 \text{ KB} = 2^{12} \text{ bytes}$).

### 2.1 Address Translation Mechanics
A logical address generated by the CPU consists of two parts:

$$
\text{Logical Address} = [ \text{Page Number } (p) \mid \text{Page Offset } (d) ]
$$

- For a 32-bit address space with $4 \text{ KB}$ page size:
  - Page offset $d$: $12 \text{ bits}$ ($2^{12} = 4096$).
  - Page number $p$: $32 - 12 = 20 \text{ bits}$ ($2^{20} = 1,048,576$ pages).
- The MMU indexes the process's page table using $p$ to find frame number $f$.
- Physical address formed: $[ f \cdot \text{PageSize} + d ]$.

### 2.2 Translation Lookaside Buffer (TLB)
Because page tables reside in main memory, every memory access would require two physical memory accesses (one for page table lookup, one for data).
- The TLB is high-speed associative hardware cache storing recently used $(p, f)$ translations.
- **Effective Memory Access Time (EMAT):**

$$
\text{EMAT} = h \cdot (t_{\text{TLB}} + t_{\text{RAM}}) + (1 - h) \cdot (t_{\text{TLB}} + 2 \cdot t_{\text{RAM}})
$$

Where $h$ is the TLB hit ratio, $t_{\text{TLB}}$ is TLB lookup latency (e.g., $1 \text{ ns}$), and $t_{\text{RAM}}$ is main memory access latency (e.g., $100 \text{ ns}$).

---

## 3. Virtual Memory and Demand Paging

Virtual memory allows execution of processes that are not completely in physical memory, providing an address space much larger than physical RAM.

### 3.1 Page Fault Handling Sequence
1. CPU references logical address whose page table entry has valid-invalid bit $= 0$.
2. Hardware MMU traps to the OS kernel (**Page Fault Trap**).
3. OS saves process state and verifies whether reference was a valid memory location.
4. If valid, OS locates an empty physical frame in RAM (or evicts a victim page).
5. OS issues asynchronous disk I/O to read the required page from swap space into the allocated frame.
6. When disk read completes, OS updates page table entry (sets frame number, sets valid bit $= 1$).
7. OS restarts the instruction that caused the page fault.

---

## 4. Page Replacement Algorithms

When a page fault occurs and all physical frames are occupied, the OS must select a victim page to evict to disk.

| Algorithm | Replacement Strategy | Properties & Trade-offs |
|---|---|---|
| **FIFO (First-In, First-Out)** | Evicts oldest loaded page | Simple, but exhibits **Belady's Anomaly** (allocating more physical frames can paradoxically increase page fault frequency). |
| **Optimal (OPT / MIN)** | Evicts page that will not be used for the longest period in the future | **Provably lowest possible page fault rate**; impossible to implement in practice because future references cannot be known. Used as a benchmark. |
| **LRU (Least Recently Used)** | Evicts page that has not been referenced for the longest period in the past | Excellent practical performance; requires hardware counter or stack timestamps. |
| **Clock (Second-Chance)** | Circular FIFO buffer inspecting reference bits ($0$ or $1$) | Practical hardware-friendly approximation of LRU used in modern kernels. |
