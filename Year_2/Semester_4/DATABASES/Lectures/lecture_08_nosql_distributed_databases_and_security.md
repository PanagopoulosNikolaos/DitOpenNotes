## 1. Περιορισμοί των Παραδοσιακών RDBMS και Εμφάνιση των NoSQL
Τα κλασικά σχεσιακά συστήματα (RDBMS) προσφέρουν ισχυρές εγγυήσεις ACID και ευέλικτη SQL, ωστόσο παρουσιάζουν περιορισμούς σε σύγχρονα σενάρια Big Data:
- **Κάθετη έναντι Οριζόντιας Κλιμάκωσης (Vertical vs Horizontal Scaling):** Τα RDBMS κλιμακώνονται κυρίως κάθετα (ισχυρότερος server με περισσότερη RAM/CPU). Τα NoSQL σχεδιάστηκαν για οριζόντια κλιμάκωση (sharding) σε εκατοντάδες φθηνά υπολογιστικά μηχανήματα (commodity servers).
- **Άκαμπτο Σχήμα (Rigid Schema):** Ανάγκη για συχνές αλλαγές σχήματος (`ALTER TABLE`) σε ημι-δομημένα δεδομένα.
- **Υψηλό Κόστος Συνενώσεων (Join Overhead):** Οι συνενώσεις πολλαπλών μεγάλων πινάκων σε κατανεμημένο περιβάλλον απαιτούν τεράστια δικτυακή κίνηση (data shuffling).

## 2. Το Θεώρημα CAP (Brewer's CAP Theorem)
Σε οποιοδήποτε κατανεμημένο σύστημα αποθήκευσης δεδομένων, είναι θεωρητικά αδύνατο να εξασφαλιστούν ταυτόχρονα και οι τρεις παρακάτω ιδιότητες:
1. **Συνέπεια (Consistency - $C$):** Κάθε ανάγνωση λαμβάνει την πιο πρόσφατη εγγραφή ή σφάλμα (όλοι οι κόμβοι βλέπουν τα ίδια δεδομένα την ίδια στιγμή).
2. **Διαθεσιμότητα (Availability - $A$):** Κάθε αίτημα που λαμβάνει ένας μη-ελαττωματικός κόμβος επιστρέφει μια μη-εσφαλμένη απάντηση (χωρίς εγγύηση ότι περιέχει την πιο πρόσφατη εγγραφή).
3. **Ανοχή Κατάτμησης Δικτύου (Partition Tolerance - $P$):** Το σύστημα συνεχίζει να λειτουργεί παρά την απώλεια μηνυμάτων ή τη διακοπή επικοινωνίας μεταξύ κόμβων.

Καθώς τα δικτυακά σφάλματα ($P$) είναι αναπόφευκτα στον πραγματικό κόσμο, τα συστήματα κατηγοριοποιούνται σε:
- **CP Συστήματα (Consistency + Partition Tolerance):** Θυσιάζουν τη διαθεσιμότητα για να εξασφαλίσουν συνέπεια (π.χ. MongoDB, HBase, Redis).
- **AP Συστήματα (Availability + Partition Tolerance):** Θυσιάζουν την άμεση συνέπεια για χάρη της συνεχούς διαθεσιμότητας (π.χ. Apache Cassandra, DynamoDB, CouchDB).

### Μοντέλο BASE (έναντι ACID)
- **Basically Available:** Εγγύηση διαθεσιμότητας των δεδομένων.
- **Soft state:** Η κατάσταση των δεδομένων μπορεί να μεταβάλλεται ακόμη και χωρίς νέα είσοδο.
- **Eventual consistency:** Αν δεν υπάρξουν νέες ενημερώσεις, όλοι οι κόμβοι θα συγκλίνουν τελικά στην ίδια κατάσταση.

## 3. Κατηγορίες Συστημάτων NoSQL
1. **Βάσεις Εγγράφων (Document Stores):**
   - Αποθήκευση δεδομένων σε ημι-δομημένη μορφή JSON ή BSON (π.χ. MongoDB, CouchDB).
   - Επιτρέπουν εμφωλευμένα πεδία και πίνακες, εξαλείφοντας την ανάγκη συνενώσεων.
2. **Βάσεις Κλειδιού-Τιμής (Key-Value Stores):**
   - Απλούστατο μοντέλο: κάθε τιμή συσχετίζεται με ένα μοναδικό κλειδί (π.χ. Redis, AWS DynamoDB).
   - Εξαιρετικά υψηλή ταχύτητα προσπέλασης μέσω memory caching ($O(1)$).
3. **Βάσεις Ευρείας Στήλης (Wide-Column / Column-Family Stores):**
   - Δεδομένα οργανωμένα σε στήλες αντί για γραμμές, επιτρέποντας αραιές δομές (π.χ. Apache Cassandra, Google Bigtable).
   - Ιδανικές για χρονοσειρές και αναλύσεις μεγάλου όγκου δεδομένων.
4. **Βάσεις Γράφων (Graph Databases):**
   - Αναπαράσταση δεδομένων ως κόμβοι, ακμές και ιδιότητες (π.χ. Neo4j).
   - Βελτιστοποιημένες για διασχίσεις πολύπλοκων δικτυακών σχέσεων (κοινωνικά δίκτυα, ανίχνευση απάτης).

## 4. Ασφάλεια Βάσεων Δεδομένων και Έλεγχος Πρόσβασης

### Έλεγχος Πρόσβασης βάσει Ρόλων (Role-Based Access Control - RBAC)
- Οι χρήστες δεν λαμβάνουν δικαιώματα απευθείας, αλλά εντάσσονται σε ρόλους:
```sql
-- Δημιουργία ρόλου και εκχώρηση δικαιωμάτων
CREATE ROLE data_analyst;
GRANT SELECT ON employees, departments TO data_analyst;
GRANT data_analyst TO user_nikos;
```

### Όψεις (Views) για Απόκρυψη Δεδομένων
- Δημιουργία εικονικού πίνακα που περιέχει μόνο τα επιτρεπόμενα πεδία ή γραμμές:
```sql
CREATE VIEW public_employee_info AS
SELECT employee_id, first_name, last_name, department_id
FROM employees;
-- Απόκρυψη του πεδίου salary και τραπεζικών λογαριασμών
```

### Αποτροπή Επιθέσεων SQL Injection
- **SQL Injection:** Έγχυση κακόβουλου κώδικα SQL μέσω εισόδων χρήστη που δεν καθαρίζονται.
- **Αντιμετώπιση:** Χρήση παραμετροποιημένων ερωτημάτων (Parameterized Queries / Prepared Statements) και Stored Procedures:
```python
# Ασφαλής εκτέλεση με Prepared Statement
cursor.execute(
    "SELECT * FROM users WHERE username = %s AND password_hash = %s",
    (input_username, input_hash)
)
```
