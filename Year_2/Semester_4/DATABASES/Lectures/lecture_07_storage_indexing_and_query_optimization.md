# Διάλεξη 7: Αποθήκευση, Ευρετηρίαση και Βελτιστοποίηση Ερωτημάτων (Storage, Indexing & Query Optimization)

## 1. Οργάνωση Αρχείων και Δίσκου (Storage Organization)
Τα συστήματα βάσεων δεδομένων αποθηκεύουν πληροφορία σε μόνιμη δευτερεύουσα μνήμη (HDD, SSD):
- **Μπλοκ / Σελίδες (Blocks / Pages):** Η ελάχιστη μονάδα μεταφοράς I/O μεταξύ δίσκου και κύριας μνήμης (συνήθως 4 KB έως 16 KB).
- **Οργάνωση Σωρού (Heap File Organization):** Οι εγγραφές τοποθετούνται οπουδήποτε υπάρχει ελεύθερος χώρος στο αρχείο, χωρίς συγκεκριμένη ταξινόμηση. Ταχεία εισαγωγή ($O(1)$), αργή αναζήτηση ($O(N)$ σειριακή σάρωση).
- **Ταξινομημένα Αρχεία (Sequential / Sorted Files):** Οι εγγραφές είναι αποθηκευμένες ταξινομημένες βάσει ενός κλειδιού αναζήτησης. Επιτρέπουν δυαδική αναζήτηση ($O(\log_2 B)$ blocks), αλλά απαιτούν ακριβές αναδιοργανώσεις κατά την εισαγωγή.

## 2. Δομές Ευρετηρίασης (Indexing)
Ένα ευρετήριο (index) είναι μια βοηθητική δομή δεδομένων που επιταχύνει την ανάκτηση εγγραφών βάσει ενός κλειδιού αναζήτησης (search key).

### Κατηγοριοποίηση Ευρετηρίων
- **Πρωτεύον / Ομαδοποιημένο Ευρετήριο (Clustered / Primary Index):** Ορίζεται σε πεδίο βάσει του οποίου είναι ταξινομημένο το ίδιο το φυσικό αρχείο δεδομένων. Μπορεί να υπάρχει μόνο ένα ομαδοποιημένο ευρετήριο ανά πίνακα.
- **Δευτερεύον / Μη Ομαδοποιημένο Ευρετήριο (Unclustered / Secondary Index):** Η φυσική σειρά των εγγραφών δεν συμπίπτει με τη σειρά του ευρετηρίου. Περιέχει δείκτες προς τις πραγματικές θέσεις εγγραφών.
- **Πυκνό Ευρετήριο (Dense Index):** Υπάρχει μία εγγραφή στο ευρετήριο για κάθε τιμή κλειδιού αναζήτησης.
- **Αραιό Ευρετήριο (Sparse Index):** Υπάρχουν εγγραφές μόνο για ορισμένα μπλοκ (απαιτεί ταξινομημένο αρχείο δεδομένων).

## 3. Ευρετήρια B+ Δένδρων (B+ Tree Indexing)
Το B+ δένδρο αποτελεί την de-facto δομή ευρετηρίασης στα σύγχρονα RDBMS (PostgreSQL, MySQL, Oracle):
- **Ισοζυγισμένο Δένδρο (Balanced Tree):** Όλα τα φύλλα βρίσκονται ακριβώς στο ίδιο βάθος.
- **Ιδιότητες Κόμβων (Τάξη $M$):**
  - Κάθε εσωτερικός κόμβος περιέχει το πολύ $M-1$ κλειδιά αναζήτησης και $M$ δείκτες προς υποδένδρα.
  - Κάθε κόμβος (εκτός της ρίζας) είναι τουλάχιστον μισογεμάτος ($\lceil M/2 \rceil$ δείκτες).
  - Όλα τα δεδομένα/δείκτες εγγραφών βρίσκονται αποκλειστικά στα **φύλλα**.
  - Τα φύλλα είναι συνδεδεμένα μεταξύ τους ως **διπλά συνδεδεμένη λίστα**, επιτρέποντας ταχύτατες αναζητήσεις εύρους τιμών (`BETWEEN`, `>`, `<`).
- **Υπολογιστική Πολυπλοκότητα:**
  - Αναζήτηση, Εισαγωγή, Διαγραφή: $O(\log_B N)$ προσπελάσεις μπλοκ δίσκου (συνήθως 3-4 I/O για δισεκατομμύρια εγγραφές).

## 4. Επεξεργασία και Βελτιστοποίηση Ερωτημάτων (Query Processing & Optimization)

### Στάδια Εκτέλεσης SQL Ερωτήματος
1. **Συντακτική & Σημασιολογική Ανάλυση (Parsing & Semantic Checking):** Έλεγχος ορθότητας σύνταξης, ύπαρξης πινάκων και στηλών, δικαιωμάτων. Μετατροπή σε εσωτερικό δένδρο σχεσιακής άλγεβρας.
2. **Βελτιστοποίηση Ερωτήματος (Query Optimizer):** Παραγωγή πολλαπλών ισοδύναμων σχεδίων εκτέλεσης (Execution Plans) και επιλογή του σχεδίου με το ελάχιστο εκτιμώμενο κόστος.
3. **Μηχανή Εκτέλεσης (Execution Engine):** Εκτέλεση των επιλεγμένων φυσικών τελεστών πάνω στα δεδομένα.

### Κανόνες Ισοδυναμίας Σχεσιακής Άλγεβρας (Heuristic Optimization)
- **Προώθηση Επιλογών προς τα Κάτω (Pushdown Selections):** Εκτέλεση των περιορισμών `WHERE` όσο το δυνατόν νωρίτερα για ελαχιστοποίηση των ενδιάμεσων πλειάδων πριν από δαπανηρές συνενώσεις:
  $$\sigma_{\theta}(R \bowtie S) \equiv (\sigma_{\theta}(R)) \bowtie S \quad (\text{αν το } \theta \text{ αφορά μόνο το } R)$$
- **Προώθηση Προβολών (Pushdown Projections):** Διατήρηση μόνο των απαραίτητων γνωρισμάτων για μείωση του πλάτους των εγγραφών στη μνήμη.

### Αλγόριθμοι Φυσικής Συνένωσης (Physical Join Algorithms)
1. **Εμφωλευμένοι Βρόχοι (Nested Loop Join):**
   - Για κάθε εγγραφή του εξωτερικού πίνακα $R$, σαρώνεται ο εσωτερικός πίνακας $S$. Κόστος: $B_R + B_R \cdot B_S$ I/O.
   - *Block Nested Loop:* Χρήση buffer μνήμης για φόρτωση πολλών blocks του $R$ ταυτόχρονα.
   - *Index Nested Loop:* Αν υπάρχει ευρετήριο στο $S$, κόστος: $B_R + |R| \cdot \text{Cost}(Index)$.
2. **Συνένωση με Ταξινόμηση-Συγχώνευση (Sort-Merge Join):**
   - Ταξινόμηση και των δύο σχέσεων ως προς το γνώρισμα συνένωσης (αν δεν είναι ήδη ταξινομημένες).
   - Ταυτόχρονη σειριακή σάρωση και συγχώνευση. Αποδοτικό για μεγάλα σύνολα δεδομένων.
3. **Συνένωση με Κατακερματισμό (Hash Join):**
   - *Φάση Κατασκευής (Build Phase):* Δημιουργία πίνακα κατακερματισμού στη μνήμη για τη μικρότερη σχέση $R$.
   - *Φάση Ανίχνευσης (Probe Phase):* Σάρωση της σχέσης $S$ και αντιστοίχιση μέσω της συνάρτησης hash.
   - Εξαιρετικά αποδοτικό για συνενώσεις ισότητας (`=`) όταν η μία σχέση χωράει στη μνήμη.
