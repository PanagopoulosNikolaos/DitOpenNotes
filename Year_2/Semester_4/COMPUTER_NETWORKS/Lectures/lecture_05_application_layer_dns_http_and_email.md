# Διάλεξη 5: Επίπεδο Εφαρμογής (HTTP, DNS, Email και Sockets)

## 1. Αρχιτεκτονικές Εφαρμογών Δικτύου
Οι εφαρμογές δικτύου αποτελούν τον κύριο λόγο ύπαρξης των υποκείμενων δικτυακών υποδομών. Βασίζονται σε δύο θεμελιώδεις αρχιτεκτονικές:

### Μοντέλο Πελάτη-Εξυπηρετητή (Client-Server Architecture)
- **Εξυπηρετητής (Server):** Πάντα ενεργός host (always-on), διαθέτει στατική και γνωστή IP διεύθυνση, εξυπηρετεί αιτήματα από πολλούς πελάτες ταυτόχρονα. Συνήθως φιλοξενείται σε κέντρα δεδομένων (data centers).
- **Πελάτης (Client):** Επικοινωνεί με τον εξυπηρετητή για να ζητήσει υπηρεσίες, μπορεί να έχει δυναμική IP διεύθυνση, δεν επικοινωνεί απευθείας με άλλους πελάτες.

### Μοντέλο Ομότιμων Κόμβων (Peer-to-Peer - P2P Architecture)
- Δεν υπάρχει κεντρικός πάντα ενεργός εξυπηρετητής.
- Τυχαία συνδεδεμένα τερματικά συστήματα (peers) επικοινωνούν απευθείας μεταξύ τους.
- **Αυτο-κλιμακωσιμότητα (Self-scalability):** Κάθε νέος κόμβος που ζητά αρχεία προσφέρει ταυτόχρονα χωρητικότητα εξυπηρέτησης σε άλλους κόμβους. Παραδείγματα: BitTorrent, διανεμημένα δίκτυα blockchain.

## 2. Το Πρωτόκολλο HTTP (Hypertext Transfer Protocol)
Το HTTP αποτελεί τη βάση του Παγκόσμιου Ιστού (World Wide Web). Χρησιμοποιεί το TCP ως υποκείμενο πρωτόκολλο μεταφοράς (προεπιλεγμένη θύρα 80 για HTTP, 443 για HTTPS).

### Χαρακτηριστικά HTTP
- **Stateless (Χωρίς διατήρηση κατάστασης):** Ο εξυπηρετητής δεν διατηρεί πληροφορίες για προηγούμενα αιτήματα του πελάτη. Η διατήρηση συνόδου (session) επιτυγχάνεται μέσω Cookies και Tokens.
- **Μη Επίμονες vs Επίμονες Συνδέσεις (Non-Persistent vs Persistent HTTP):**
  - *HTTP/1.0:* Μη επίμονη σύνδεση. Κάθε αντικείμενο ιστού (HTML, εικόνα) απαιτεί νέο TCP 3-way handshake. Χρόνος ανά αντικείμενο: $2 \cdot \text{RTT} + \text{Χρόνος Μετάδοσης}$.
  - *HTTP/1.1:* Επίμονη σύνδεση (Persistent TCP). Πολλαπλά αιτήματα και απαντήσεις αποστέλλονται μέσω της ίδιας ανοικτής σύνδεσης TCP. Υποστήριξη Pipelining.
  - *HTTP/2:* Πολυπλεξία πλαισίων (binary framing), ένα κοινό TCP connection, προτεραιοποίηση πόρων και Server Push.
  - *HTTP/3 (QUIC):* Μετάβαση πάνω από UDP για εξάλειψη του Head-of-Line blocking στο επίπεδο μεταφοράς και ταχύτερη αποκατάσταση κρυπτογραφημένης σύνδεσης 0-RTT.

### Μέθοδοι HTTP
- `GET`: Ανάκτηση πόρου από τον εξυπηρετητή.
- `POST`: Αποστολή δεδομένων (π.χ. φόρμες) για επεξεργασία.
- `PUT`: Αντικατάσταση ή δημιουργία συγκεκριμένου πόρου.
- `DELETE`: Διαγραφή καθορισμένου πόρου.
- `HEAD`: Όμοιο με το GET, αλλά επιστρέφει μόνο τις επικεφαλίδες (headers).

## 3. Σύστημα Ονομάτων Χώρου (DNS - Domain Name System)
Το DNS είναι μια ιεραρχική, κατανεμημένη βάση δεδομένων που μεταφράζει αναγνώσιμα ονόματα χώρου (π.χ. `www.dit.uoi.gr`) σε διευθύνσεις IP (π.χ. `195.130.121.200`).

### Ιεραρχία Διακομιστών DNS
1. **Root DNS Servers:** 13 λογικές ομάδες ριζικών εξυπηρετητών παγκοσμίως.
2. **Top-Level Domain (TLD) Servers:** Υπεύθυνοι για καταλήξεις όπως `.com`, `.org`, `.gr`, `.edu`.
3. **Authoritative DNS Servers:** Οι εξυπηρετητές του οργανισμού που περιέχουν τις επίσημες εγγραφές για τους hosts του.
4. **Local DNS Resolver (Επιλύτης):** Ο τοπικός διακομιστής (συνήθως του ISP ή εταιρικού δικτύου) που λαμβάνει τα ερωτήματα από τους πελάτες.

### Είδη Ερωτημάτων DNS
- **Επαναληπτικό (Iterative Query):** Ο τοπικός διακομιστής ρωτά διαδοχικά τον root, μετά τον TLD και τέλος τον authoritative server.
- **Αναδρομικό (Recursive Query):** Κάθε εξυπηρετητής αναλαμβάνει να ρωτήσει τον επόμενο και να επιστρέψει την τελική απάντηση.

### Τύποι Εγγραφών Πόρων (Resource Records - RR)
- `A`: Αντιστοίχιση ονόματος host σε IPv4 διεύθυνση.
- `AAAA`: Αντιστοίχιση ονόματος host σε IPv6 διεύθυνση.
- `NS`: Εξυπηρετητής ονομάτων για συγκεκριμένη ζώνη.
- `CNAME`: Κανονικό όνομα (ψευδώνυμο / alias) για έναν host.
- `MX`: Εξυπηρετητής ηλεκτρονικού ταχυδρομείου (Mail Exchange).

## 4. Ηλεκτρονικό Ταχυδρομείο (Email Protocols)
Η αρχιτεκτονική του email διαχωρίζεται σε πρωτόκολλα προώθησης και ανάκτησης:
- **SMTP (Simple Mail Transfer Protocol):** Πρωτόκολλο προώθησης (push protocol) πάνω από TCP (θύρα 25 ή 587 με STARTTLS) για μεταφορά μηνυμάτων μεταξύ εξυπηρετητών και από τον πελάτη στον εξυπηρετητή.
- **IMAP (Internet Message Access Protocol):** Πρωτόκολλο ανάκτησης (pull protocol) πάνω από TCP (θύρα 143 ή 993 για IMAPS). Επιτρέπει τη διατήρηση των μηνυμάτων στον εξυπηρετητή και συγχρονισμό φακέλων σε πολλαπλές συσκευές.
- **POP3 (Post Office Protocol v3):** Απλό πρωτόκολλο λήψης (θύρα 110 ή 995). Κατεβάζει τα μηνύματα τοπικά και συνήθως τα διαγράφει από τον εξυπηρετητή.

## 5. Προγραμματισμός Υποδοχών (Socket Programming)
Η υποδοχή (socket) είναι η λογική διεπαφή μεταξύ της διεργασίας εφαρμογής και του λειτουργικού συστήματος (επίπεδο μεταφοράς).

### Τύποι Sockets
1. **Stream Sockets (`SOCK_STREAM`):** Χρησιμοποιούν το TCP. Παρέχουν αξιόπιστη, προσανατολισμένη σε σύνδεση, συνεχή ροή bytes χωρίς απώλειες και με διατήρηση σειράς.
2. **Datagram Sockets (`SOCK_DGRAM`):** Χρησιμοποιούν το UDP. Παρέχουν αναξιόπιστη αποστολή αυτοδύναμων πακέτων χωρίς εγγύηση άφιξης, διατήρηση ορίων μηνύματος (message boundaries).

```python
# Παράδειγμα TCP Echo Server σε Python
import socket

server_socket = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
server_socket.bind(('0.0.0.0', 8080))
server_socket.listen(5)
print("Server listening on port 8080...")

client_conn, client_addr = server_socket.accept()
data = client_conn.recv(1024)
client_conn.sendall(b"ECHO: " + data)
client_conn.close()
server_socket.close()
```
