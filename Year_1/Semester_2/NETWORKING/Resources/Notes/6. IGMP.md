# The IGMP Protocol (Internet Group Management Protocol)

IGMP is a communication protocol used to manage membership in multicasting groups in IP networks. It constitutes a fundamental component of multiple receiver communication, allowing hosts and routers to coordinate the transmission of packets to multiple destinations simultaneously. This article presents the main features of the IGMP protocol, its architecture and mode of operation.

## Basic Multicasting Concepts

Multicasting is a method of transmitting data to multiple receivers simultaneously. Unlike broadcasting (sending to all) and unicasting (sending to one), multicasting allows sending to selected groups of devices.

### Multicast Group Structure

Members of a multicasting group can be:

- Central computers (hosts)
- Routers that serve multicasting groups

### Multicast Routers

Multicast routers play a critical role in managing and forwarding multicast traffic. They maintain lists of groups for which there is interest in the network. Each list contains only the groups for which there is interest at the local level.

Their function includes:

- Discovery of devices that wish to receive multicast traffic
- Maintenance of multicast routing tables
- Implementation of multicast routing protocols (including IGMP)

## IGMP Message Structure

IGMP messages are encapsulated in IP packets and have a specific structure.

### Message Types

|   |   |   |   |
|---|---|---|---|
|Type|Binary Value|Destination IP|Description|
|General or Special Query|00010001|224.0.0.1|All systems on this subnet|
|Membership Report|00010110|Group multicast address|Membership report|
|Leave Report|00010111|224.0.0.2|All routers on this subnet|

### IGMP Packet Format

```Mermaid
graph LR
    subgraph "IGMP Header"
    A[Type] --> B[Maximum Response Time]
    B --> C[Checksum]
    C --> D[Group Address]
    end
```

Notes on the IP packet that carries IGMP:

- Has value 2 in the protocol field
- Has value 1 in the TTL (Time To Live) field

## Mapping of Class D Addresses to Physical Ethernet Addresses

The mapping of Class D (multicast) addresses to physical Ethernet addresses is done in a specific way.

### Mapping Procedure

```Mermaid
graph TD
    A[32-bit Class D Address] --> B[Extraction of last 23 bits]
    B --> C[Adding 01:00:5E at the beginning]
    C --> D[Physical Ethernet Address]
```

For example:

- Initial 23 bits of the multicast address: 0000000100000000010111100
- Subsequently, these 23 bits form part of the physical Ethernet address

## Multicast Groups Table

Routers and hosts maintain tables to manage multicast groups.

### Table Structure

|   |   |   |   |
|---|---|---|---|
|State|Interface Number|Group Address|Reference Counter|
|Free/Delaying/Idle|...|...|...|
|...|...|...|...|
|...|...|...|...|

- **State**: Can be Free, Delaying or Idle
- **Reference Counter**: Number of processes interested in the group

## Group Membership Process

The process of joining a multicasting group includes sending a Membership Report (MR).

```Mermaid
sequenceDiagram
    participant H as Host
    participant R as Router
    Note over H: Wishes to join a group
    H->>R: Membership Report (MR)
    Note over R: Adds group to table
    R->>H: Starts sending multicast packets
```

### Basic Steps for Membership

1. A host maintains a list of groups it belongs to
2. When a new group (groupid) is added, the host sends a Membership Report (MR)
3. If the host is already a member of a group with the same groupid, then it sends MR on all interfaces except the one from which the new groupid originated

## Summary

The IGMP protocol constitutes a fundamental component of multicasting communication in IP networks. It allows efficient management of groups, reducing network traffic and optimizing data distribution to multiple receivers. Understanding the mechanisms of IGMP is critical for the design and management of modern networks that support applications such as video streaming, video conferencing, and other services that require data transmission to multiple receivers simultaneously.
